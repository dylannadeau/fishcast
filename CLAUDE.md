# CLAUDE.md

Guidance for Claude when working in this repo. Read this first, then the file you're editing.

## What this is

iOS app, SwiftUI, iOS 17+. Hyperlocal fishing forecasts: scores current conditions for the user's location and ranks Northeast/New England freshwater species. Five tabs: Dashboard, Map, Forecast, Log, Settings. Includes a WidgetKit extension.

User-facing display name is **"Anglers Edge"** (set via `CFBundleDisplayName` in `project.yml`). The internal project, bundle ID (`com.fishcast.FishCast`), Swift module, folder names, and most code identifiers (`FishCastApp`, `FishCastCard`, `FishCastWidget`) still say "FishCast" — this is intentional. Do not rename them unless explicitly asked; renaming the bundle ID would break upgrade path for existing installs.

## Build / run

The project is generated by **XcodeGen** — `project.yml` is the source of truth. Never hand-edit `.xcodeproj`.

```bash
xcodegen generate              # after any project structure change
xcodebuild -project FishCast.xcodeproj -scheme FishCast \
  -destination 'generic/platform=iOS Simulator' \
  -configuration Debug build CODE_SIGNING_ALLOWED=NO
```

Run `xcodegen generate` after: adding/removing files outside of existing source dirs, changing Info.plist properties, modifying targets, or adjusting entitlements. Adding a new `.swift` file inside an already-tracked directory does **not** require regen — sources are globbed.

CI (`.github/workflows/build.yml`) runs `xcodebuild clean build` on PRs to `main` and pushes to `develop`.

## Architecture conventions

- **MVVM, iOS 17 Observation.** View models are `@Observable` final classes pinned to `@MainActor`. Use `@State private var viewModel = SomeViewModel()` in views; bind with `@Bindable var viewModel = viewModel` inside `body` when you need bindings.
- **Services are singletons** with a static `shared`. Most are `@MainActor`; `BarometricService` and `TideService` are `actor`s.
- **Design system lives in `Utilities/DesignSystem.swift`.** Use `Color.primaryBackground`, `Color.accentGold`, `Spacing.md`, `Layout.radiusMd`, `Font.appBody`, `AppIcons.fish`, etc. Don't hardcode colors, paddings, fonts, or symbol names.
- **`FishCastCard`** is the canonical card container — wrap grouped content in it instead of building bespoke backgrounds.
- **Cross-tab navigation** goes through `AppRouter` (`Utilities/AppRouter.swift`). `ContentView` binds the `TabView` selection to it.

## Persistence (where state actually lives)

| What | Where | Format |
|------|-------|--------|
| Saved spots | `Documents/spots.json` | JSON via `SpotStore` |
| Catch log | `Documents/catches.json` | JSON via `CatchStore` |
| Pressure history (3h rolling) | `UserDefaults` key `com.fishcast.pressure.readings` | JSON via `BarometricService` |
| NOAA tide stations cache | `Caches/noaa_tide_stations.json` | JSON via `TideService` |
| Onboarding completion | `UserDefaults` via `@AppStorage(SettingsKey.onboardingComplete)` | Bool |
| Widget snapshot | App Group shared container | via `WidgetStorage` |

If you change the bundle ID, all of the above (except UserDefaults if the suite name matches) becomes inaccessible — never silently break user data.

## Scoring engine

Live in `Services/FishingConditionsEngine.swift`; species data in `Models/TargetSpecies.swift`. The full spec — factor weights, species temperature ranges, ranking modifiers, science rationale — lives in **[`docs/scoring.md`](docs/scoring.md)**. Read it before changing any weights, thresholds, or species behavior. The engine is stateless and pure; it's also the heart of the product, so changes should preserve the test surface and the back-compat fields on `FishingScore`.

## Things that have bitten us

- **`CFBundleDisplayName` permission strings.** When changing the display name, update `NSLocation*UsageDescription` and `NSPhotoLibraryUsageDescription` to match — iOS prepends the display name to the dialog title, so internal inconsistency is user-visible.
- **`fileprivate` types in `FishingConditionsEngine`.** The engine has a `fileprivate struct Context` referenced by internal helpers. If you add a stored property whose type is a nested `private enum`, Swift will reject it — relax to `fileprivate`.
- **`FishingScore` back-compat aliases.** Existing views bind to `score`, `summary`, `factors`. Spec-named computed aliases (`overallScore`, `summaryText`, `conditionFactors`) wrap them. Don't remove either set.
- **MapKit / WeatherKit / CoreLocation log `Failed to locate resource named "default.csv"`** — benign framework noise, ignore.
- **WeatherKit is billed per-request.** Prefer `WeatherService.fullForecast(for:)` over separate current/hourly/daily calls. Dashboard refreshes batch into one call.
- **Hourly forecast horizon is 72h.** Dashboard's "next best window" and 3-day outlook depend on this — don't reduce it without checking those consumers.

## When adding a new species

1. Add a case to `TargetSpecies` enum (`Models/TargetSpecies.swift`). Raw value is the display name.
2. Append a `SpeciesProfile` to `SpeciesDatabase.all` with bladder type, tolerance + peak temp ranges (°F), peak seasons, and SF Symbol.
3. Add a tip case in `FishingConditionsEngine.tip(for:context:)`.
4. Add any per-species time-of-day bonus in `FishingConditionsEngine.behaviouralTimeBonus(species:context:)`.
5. Apply temperature ceilings if applicable in `applyTemperatureCeilings(score:species:tempF:)`.

Verify with `xcodebuild build` — the `switch` statements on `TargetSpecies` are exhaustive, so the compiler will flag any case you missed.

## When adding a new tab or top-level screen

1. Add a new `case` to `AppRouter.Tab` with a unique `Int` raw value.
2. Add a `.tabItem` + `.tag(AppRouter.Tab.newCase)` to `ContentView`.
3. Use `NavigationStack` at the root of the new screen; `.toolbarBackground(Color.primaryBackground, for: .navigationBar)` for consistent styling.

## Quick checklist before declaring done

- `xcodegen generate` if `project.yml` changed.
- `xcodebuild ... build` returns `** BUILD SUCCEEDED **` with no warnings.
- Touched `Info.plist` properties? Verify with `PlistBuddy -c "Print :KEY" FishCast/Info.plist`.
- Touched persistence? Confirm a fresh install still works (no migration assumed unless you write one).
- Touched user-visible copy? Grep for the old string — onboarding, settings, push titles, and email subjects all carry copy.
